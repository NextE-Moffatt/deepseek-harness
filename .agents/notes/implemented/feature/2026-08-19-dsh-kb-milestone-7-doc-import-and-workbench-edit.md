# Agent Note: dsh-kb milestone 7 — raw-note document import and workbench card editing

Status: implemented

English | [中文](2026-08-19-dsh-kb-milestone-7-doc-import-and-workbench-edit.zh.md)

## Problem

Milestones 1–6 closed the agent loop: card write/read/search, knowledge packs, team governance, recap, the web workbench, read-only MCP exposure, and unified dual-library search. Two gaps remain for the product direction (a WorkBuddy-like knowledge core for security/ops/operations scenes): the ingest seam treats existing team documents as dead weight — `importDir` parses card-shaped `*.md` files and counts every raw note as skipped, so the knowledge base cannot absorb the team's existing markdown backlog — and the human workbench is read-only on card content, so a person cannot correct a card's fields after import or agent distillation (the [milestone-5 note](2026-08-19-dsh-kb-milestone-5-workbench-and-mcp.md) deliberately rejected a card-edit operation). Milestone 7 (B1+B2) closes the 存量入口 (document import) and the 人机协同治理 (human edit) paths.

## Decision

**B1 — `importDir` wraps raw markdown notes into draft cards instead of skipping them.** The wrap rule set: a `*.md` file that does not open with a `---` front-matter fence and has at least one non-heading content line is wrapped; the inferred card lands as a personal `draft` in the caller's tier (P2 by default) with `有效期` = today + `cardTtlDays` (new `ImportOptions.cardTtlDays`, default 90; `KbService.importDir` forwards its config value and an explicit option wins). Field inference is deterministic: `title` = the first `# ` heading line, falling back to the file basename without extension; `核心结论` = the body's non-heading, non-empty lines joined with `\n`, truncated to 1000 chars; `适用条件` = the first non-heading, non-empty body line, truncated to 200 chars (the parser requires a non-empty 适用条件, so the "first line" choice replaces the impossible "default empty"); `type` = `howto` (the generic operational-document default — no reliable inference from a raw note); `应做`/`不应做` = empty arrays (the parser permits empty for imported cards; `kb_write`'s at-least-one rule stays tool-side); `标签` = the immediate parent directory name relative to the source dir as a single tag when the file is nested at least one level, none for files directly in the source dir; `来源` = the source file path; `责任人` = the fixed marker `导入` (the importing entity is unknown; the workbench human corrects it later). Heading lines are dropped from the conclusion and condition so the serialized card never carries a `## `-leading line that would break re-parsing. The checkpoint records the wrapped card's generated id exactly like a card-shaped import, so a changed source re-wraps into the same card in place, preserving the card's current 状态 (the existing re-import contract); unchanged wrapped files skip via the checkpoint. Files that open with `---` but fail card parsing are malformed cards, never wrapped — wrapping would silently destroy a broken card's intended structure — and are skipped and counted. Empty or heading-only files are skipped and counted. Non-`.md` files are now enumerated, skipped, and counted in `skippedRaw` (previously invisible to the walker); they are not checkpointed, so each run recounts the files it ignored.

**B2 — the workbench edits card content through one new Remote and one new service method.** `KbService.editCard(root, id, patch, options?)` resolves the card across the personal and team libraries (like `card`), validates the patch at the wire boundary (closed field set, closed enums, calendar dates, non-empty strings, tag list, `应做`/`不应做` arrays that may become empty), applies it preserving `id` / `库` / `状态` (identity, library moves, and status transitions stay with the dual gate and the state machine), and rewrites in place via `PersonalCardStore.rewrite` or `TeamCardStore.rewrite`. Editable fields: `type`, `title`, `适用条件`, `核心结论`, `应做`, `不应做`, `反例`, `来源`, `责任人`, `有效期`, `标签`. Personal and team cards are same-privilege; a team edit requires `approved: true` in the request when `KbConfig.teamWriteApproval` is true (default), enforced inside `editCard` — the operation that makes the decision — because the human workbench has no separate approver (the human is the approver; the tool `ask` seam requires an open agent turn and a composed approval service, neither guaranteed by the workbench composition). Personal edits never need approval; the model tool path keeps its unchanged `tools/pre-execute` ask gate. Every edit appends `kb/edit` to the workbench session's own log after the write succeeds — `{ id, library, fields }` with the changed field-name list; the card file stays the content source of truth (the `kb/write` pattern). An edit whose fields are all unchanged performs no write and appends no event. The milestone-5 "no card-content editing" decision is superseded for the workbench; this note cross-links it (partial supersession, both notes stay active).

**B2 concurrency is a lightweight optimistic guard, not a lock.** `KbWorkbenchCard` gains `mtime` / `size` (the file identity the ingest checkpoint already uses). The edit request carries the expected `{ mtime, size }` observed at detail load; `editCard` re-reads the file and throws a conflict error when the on-disk identity differs (「卡片已被其他会话修改，请刷新后重试」). The full lock stays deferred (D2) with its trigger condition; mtime+size identity has the documented residual of same-size edits inside the filesystem's mtime granularity.

## Alternatives considered

**Wrap every `*.md` file including front-matter-malformed ones.** Rejected: a file that opens with `---` is an attempted card, and converting it to a `howto` note would destroy the user's intended structure silently; skipping it keeps the parse failure visible so the author fixes the card.

**Derive the wrapped card's `type` from content heuristics (keyword scoring) and its tags from the file name.** Rejected: no reliable signal exists in an arbitrary raw note, keyword scoring is a second hand-rolled classifier with no consumer, and per-file tags would be unique per card — useless for pack subscription. The fixed `howto` default and the directory-derived single tag are deterministic and teachable; the workbench edit corrects the category.

**Route the workbench team edit through the tool `ask` approval seam (`approval.request`).** Rejected: the seam requires an open agent turn on the session and a composed approval service — the workbench session has neither in the shipped composition — and the human clicking save IS the approver, so the ask would be self-approval theater. The explicit `approved` flag enforced in `editCard` carries the approval decision with the operation and degrades closed (a missing flag denies a team edit under the default policy).

**Guard the edit with a content hash.** Rejected: the ingest checkpoint already defines file identity as mtime+size, and a hash read would add a full file read to every edit; the same identity and its documented sub-second residual apply.

## Consequences

`packages/kb/kb-core/src/ingest.ts` gains the wrap path (raw-note inference, non-`.md` counting, checkpoint round-trip for wrapped ids) and `ImportOptions.cardTtlDays`; `KbService.importDir` forwards its config default. `KbService.editCard` plus the `kb/edit` event land in kb-core: the event joins `SessionEventMap`, `KNOWN_SESSION_EVENT_TYPES`, the generated persistence catalog, and the invariant companion's `validateEdit`. `packages/kb/kb-web` gains `@Remote('edit')` (thin wrapper: resolve → editCard → append `kb/edit` → return the refreshed card view) and `KbWorkbenchCard` carries `mtime`/`size` for the conflict check. The workbench client adds an 编辑 affordance on the card detail: an edit form over the content fields, a team-edit confirmation, and a conflict error path that refreshes the detail. The keyless assembled-snapshot lane gains an edit case through the connection fixture (`kbWorkbench/edit`); the golden files re-record. Consumption surfaces are unchanged: kb tools (no new tool), the read-only MCP server, knowledge-pack injection (reads `list()` faces), and the unified dual-library search (the index re-syncs edited files by mtime/size on the next query). Tests: per-file 100% on every touched src file — the ingest spec's wrap matrix, an edit spec, the invariant spec's `kb/edit` cases, the kb-web spec's edit/approval/conflict cases, the loader-composition chains (real workspace edit through the Loader), and the client component spec's edit-form cases. Docs update: `docs/subsystems/kb.md` + zh (session events, workbench section), the persistence catalog + zh, the kb-core/kb-web/ui-kb-workbench READMEs + zh (the raw-note-import and no-card-editing limitations are replaced by the shipped behavior), and the generated cordis catalogs.

Deferred with trigger conditions, recorded in the READMEs: B3 team-docs web write (a read-only-boundary relaxation decision), a model-facing `kb_edit` tool (a model edit flow), workbench tier moves (a user request), and the full edit lock D2 (real concurrent-edit evidence).
